## Long-term data behavior
- **Refresh policy**: public-data tools (weather, crypto, news, currency) fetch live on each page open through server actions with react-query stale times of 2–5 minutes; no cron refresh — data is per-viewer, not user records. Notes/reminders sync to the server on every change when signed in and always persist to localStorage first, so they work fully offline and re-sync on next load.
- **Growth**: users, sessions (30-day expiry, pruned on sign-in), reviews (max 1 per user, DB unique index), feedback, announcements, scores (append-only, leaderboard aggregates best-per-game + total), quiz_sessions (one active per user), notes, reminders, short_links, per-user preferences JSON.
- **Ordering**: leaderboard by total points desc; reviews newest first; announcements newest first; notes by updated_at desc.
- **Time semantics**: created_at stored as epoch-ms instants, rendered viewer-local; reminder due times are user-entered local wall times stored with the entered date/time string and compared client-side.
- **Auth/security**: passwords hashed server-side (SHA-256 + per-user random salt via WebCrypto); session = random 256-bit token stored server-side, kept by the client in localStorage; role lives ONLY in the users table and every admin action re-checks it from the session on the server; first registered account becomes admin (bootstrap, documented in Setup page), admins can promote others; email verification uses a 6-digit code — with no mail service configured in this build the code is shown in-app and clearly labeled demo delivery, and the Setup page names the SMTP/RESEND secret a production deployment must add.

## Voice picker bug fix, wake latency push, creator branding (2026-11-26, user-tested reports)
- **Bug: changing the voice style changed nothing audible.** Three stacked causes, all fixed: (1) Profile's Listen demos passed the exact-voice override (`voiceName`), so every demo played in the same voice — demos now always preview the style itself, choosing a style clears the override, and the override select is labeled as overriding the styles; (2) the four female presets had near-identical `prefer` lists, so all resolved to the same installed voice with ±0.1 rate/pitch differences — presets now carry a `gender`, deliberately different preference lists and wider rate/pitch spreads, and `pickVoice` heavily penalizes wrong-gender voices (−80) and rewards right-gender (+25), so male styles never speak in a female voice when the device has both; (3) the Chat voice loop captured render-scope speak options in long-lived closures, so a mid-conversation style change never reached the speaker — the loop now reads `speakOptsRef`, updated every render, so a switch applies to the very next sentence.
